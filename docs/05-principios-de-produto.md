# 05 — Princípios de Produto

## 1. Consistência acima da perfeição

O produto deve incentivar continuidade e não execução perfeita.

## 2. Captura mínima

O sistema deve solicitar o mínimo possível de informação manual.

## 3. Automação primeiro

Antes de criar um novo campo manual, deve-se perguntar:

> Este dado pode ser obtido, inferido ou calculado automaticamente?

## 4. Dados precisam gerar valor

Nenhum dado deve existir apenas porque “seria interessante registrar”.

Cada informação deve contribuir para:

- decisão;
- acompanhamento;
- histórico;
- análise;
- automação.

## 5. Modularidade

Saúde, treino, alimentação, finanças e estudos devem funcionar como módulos independentes, mas integráveis.

## 6. Histórico importa

O sistema deve permitir observar evolução ao longo de semanas, meses e anos.

## 7. Flexibilidade

Metas e rotinas mudam.

O produto deve aceitar essas mudanças sem exigir reconstrução completa.

## 8. Experiência antes do dashboard

O dashboard é consequência.

Primeiro o sistema precisa tornar fácil registrar e obter dados confiáveis.

## 9. O dado pertence ao usuário

A estrutura deve permitir exportação, portabilidade e transparência sobre aquilo que está armazenado.
